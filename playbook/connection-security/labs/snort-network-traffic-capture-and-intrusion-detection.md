# Lab: Network Traffic Capture and Intrusion Detection With Snort

## Overview

This lab demonstrated how a dual-homed Linux sniffer could capture traffic from internal and external network segments, save packet capture (PCAP) files with tcpdump, inspect network activity with Wireshark, and analyze suspicious traffic with Snort. The workflow connected traffic collection, signature-based alert generation, and packet-level validation to show how security analysts investigate password attacks and controlled outbound connection activity in an isolated lab environment.

## Lab Summary

This lab follows the lifecycle of network traffic capture and intrusion detection:

1. The Linux sniffer was configured with two active interfaces for passive monitoring of the internal and external network segments.
2. Traffic generated by lab systems was observed to identify which interface corresponded to each network.
3. Baseline network traffic was captured to PCAP files with tcpdump and reviewed in Wireshark.
4. An authorized FTP password attack was captured and analyzed offline with Snort to generate intrusion alerts.
5. Controlled outbound test traffic was generated within the isolated environment and recorded by the sniffer.
6. The outbound capture was filtered and followed in Wireshark to examine the associated Transmission Control Protocol (TCP) stream.

## Key Takeaways

- A passive network sniffer can monitor traffic without receiving an Internet Protocol (IP) address on its capture interfaces.
- Promiscuous mode allows an interface to receive traffic beyond frames addressed directly to the sniffer.
- tcpdump can capture large amounts of traffic efficiently and save packets to PCAP files for later analysis.
- The `-s 0` tcpdump option captures the complete packet instead of the tool's smaller default snapshot length.
- Snort can analyze an existing PCAP file and generate an `alert.ids` file when traffic matches configured signatures.
- Numerous authentication attempts within a short period can indicate automated password-guessing activity.
- Wireshark display filters and Follow TCP Stream help isolate meaningful traffic from a larger capture.
- Capture, detection, and analysis tools provide different views of the same event and are most useful when used together.

## Workflow

### Configure the Dual-Homed Sniffer

The Kali Linux sniffer was accessed, its active interfaces were reviewed, and both Ethernet interfaces were activated without assigning them normal host addresses.

**Purpose**

- Prepare the system to monitor both the internal local area network (LAN) and external wide area network (WAN) segments.
- Reduce the chance that the capture interfaces would participate in normal network communication.
- Allow the system to receive traffic for passive analysis.

**Result**

- The sniffer displayed `eth0`, `eth1`, and the loopback interface.
- The Ethernet interfaces were active without normal network addresses, while the loopback address remained available.

### Identify the Internal and External Interfaces

Short tcpdump sessions were started on each interface while other lab systems generated traffic. The observed address ranges were used to map each interface to the correct network segment.

**Purpose**

- Confirm which physical or virtual interface monitored each side of the network.
- Prevent later captures from being taken on the wrong segment.
- Verify that the sniffer could observe live Internet Protocol version 4 (IPv4) traffic.

**Result**

- Traffic from the `192.168.1.0/24` network identified the internal segment.
- Traffic from the `216.0.0.0/8` network identified the external segment.
- The exact interface-to-network assignment was verified from the packets rather than assumed.

### Capture and Review Baseline Traffic

Traffic from both network segments was written to `capnet1.cap` and `capnet2.cap`, then opened in Wireshark for inspection.

**Purpose**

- Establish normal traffic visibility before investigating suspicious activity.
- Practice writing full packets to PCAP files instead of displaying every packet in the terminal.
- Confirm that Wireshark could open and interpret captures created by tcpdump.

**Result**

- Separate PCAP files were created for the internal and external segments.
- Wireshark displayed the addresses, protocols, and packet details recorded in each capture.

### Detect Unwanted Incoming Traffic

The internal segment was captured to `brute.cap` while a lab-provided password-testing utility generated repeated File Transfer Protocol (FTP) authentication attempts against the authorized target. Snort then analyzed the completed capture offline.

**Purpose**

- Create a known suspicious traffic pattern in a controlled environment.
- Demonstrate how repeated login attempts appear in packet captures.
- Use Snort signatures to convert captured traffic into actionable alerts.

**Result**

- Snort generated an `alert.ids` file from `brute.cap`.
- The alert output identified repeated activity involving the source host and TCP port 21.
- The high number of attempts occurring within seconds distinguished the activity from normal user behavior.

A lab-provided test file and connection handler were prepared on the external Kali system, then used only within the isolated virtual environment to create a predictable outbound session from the Windows server.

**Purpose**

- Demonstrate how an external listener and an internal client connection appear in network monitoring tools.
- Provide a repeatable event for validating packet filters and stream reconstruction.

## Notes

### Passive Dual-Homed Monitoring

A dual-homed sniffer uses separate interfaces to observe multiple network segments. The lab kept the capture interfaces active without normal IP assignments so the system could monitor traffic without functioning as a typical endpoint on either segment. In production networks, comparable visibility may be provided by a network hub, a switched port analyzer (SPAN) port, or a network tap.

### Capture-to-Alert Workflow

```text
Network traffic
      |
      v
tcpdump or Wireshark capture
      |
      v
PCAP file
      |
      v
Snort offline analysis
      |
      v
alert.ids
      |
      v
Analyst validation and investigation
```

### Important tcpdump Options

The lab used interface selection, disabled name resolution, full-packet capture, file output, and capture-file size limits. These options made the captures more efficient to collect and easier to analyze later.

- `-i` selected the capture interface.
- `-n`, `-nn`, or `-nnn` reduced hostname and service-name resolution.
- `-s 0` captured the complete packet.
- `-w` wrote packets to a PCAP file.
- `-C` limited the size of each capture file before rotation.

### Snort and Wireshark Roles

Snort performed signature-based inspection and produced alerts indicating traffic that matched configured rules. Wireshark provided packet-by-packet inspection, display filtering, and TCP stream reconstruction. Snort helped identify which events deserved attention, while Wireshark supplied the detailed evidence needed to understand them.

### Controlled Testing Boundary

The attack-simulation portion of the lab was performed only against systems supplied within the authorized, isolated environment. Exact test-file generation, delivery, execution, and handler commands are intentionally omitted from this public-facing draft. The comments in the Commands Used section identify the corresponding lab pages and steps so they can be restored later in a private reference if needed.

## Commands Used

### Inspect and Activate the Sniffer Interfaces

```bash
ifconfig
ifconfig eth0 0.0.0.0 up
ifconfig eth1 0.0.0.0 up
tcpdump --help
```

### Identify the Monitored Network Segments

```bash
tcpdump -i eth0
tcpdump -i eth1
```

### Capture and Review Baseline Traffic

```bash
# Use the interface verified for the internal segment.
tcpdump -i eth0 -nnntt -s 0 -w capnet1.cap -C 100
wireshark capnet1.cap

# Use the interface verified for the external segment.
tcpdump -i eth1 -nnntt -s 0 -w capnet2.cap -C 100
wireshark capnet2.cap
```

### Capture and Analyze the Authorized FTP Password Test

```bash
tcpdump -i eth0 -nnntt -s 0 -w brute.cap -C 100
nmap 216.1.1.1
snort -l . -c /etc/snort/snort.conf -r brute.cap
ls
leafpad alert.ids
```

## Quick Reference

| Item | Purpose |
|------|---------|
| Dual-homed sniffer | Monitors two separate network segments from one system. |
| Promiscuous mode | Allows an interface to receive traffic not addressed directly to it. |
| PCAP | Standard file format used to store captured network packets. |
| tcpdump | Command-line tool used to capture and save network traffic. |
| `-s 0` | Captures the complete packet instead of a limited snapshot. |
| `-w` | Writes captured packets to a file. |
| `-C` | Rotates capture files after the specified size is reached. |
| Snort | Intrusion Detection System (IDS) used to inspect traffic against signatures. |
| `alert.ids` | Snort alert file containing detected suspicious activity. |
| TCP port 21 | Standard control port associated with FTP. |
| Wireshark display filter | Limits displayed packets to traffic matching defined conditions. |
| Follow TCP Stream | Reconstructs the data exchanged during a TCP conversation. |
